# 배포 문제 확인 안내

현재 배포 절차는 [README](../../README.md#배포)를 기준으로 합니다. [Cloud 작업 일지](DEVLOG.md)는 초기 PM2 환경의 과거 기록이므로 현재 Docker 환경에 그대로 적용하지 않습니다.

| 증상·상황 | 확인 순서 |
| --- | --- |
| develop 병합 후 운영이 그대로임 | 정상적인 배포 분리. develop 병합은 운영 배포를 실행하지 않음 |
| main 배포 실패 | GitHub Actions의 이미지 빌드·푸시 단계와 서버 재배포 단계 중 실패 위치 확인 |
| BE 기동 실패 | 컨테이너 상태·로그와 필수 환경변수 설정 여부 확인. 값 자체를 공유하지 않음 |
| health는 정상인데 업무 API 실패 | health는 DB·Redis 연결 검증이 아님. 업무 API 응답과 관련 로그 확인 |
| Nginx 변경 미반영 | 별도 워크플로 결과, Nginx 서버의 설정 검사와 공개 API 경로 확인 |
| 되돌리기 필요 | README의 코드·DB 복구 경계를 확인하고 배포 담당자와 조율. 코드 revert는 DB를 되돌리지 않음 |

상태·로그 확인 명령은 README의 ‘배포 후 확인’에 있습니다. 운영 재시작·DB 변경·캐시 삭제를 자동으로 수행하지 않으며, 로그를 공유할 때 접속정보·토큰·개인정보를 제외합니다.
