# 계정 탈퇴·선물 주문 동시성 보완

관련 이슈: [BE #85](https://github.com/adapterz/wku-iksan-store-BE/issues/85)

## 변경 목적

기존 탈퇴는 트랜잭션 밖에서 미사용 선물이 없는지 확인했다. 확인 직후 다른 요청이 선물을
저장하면 탈퇴가 그대로 진행돼, 해당 주문의 `receiver_id`가 `NULL`로 바뀔 수 있었다.

회원 행 잠금, 미사용 선물 확인, 활성 정지 확인, 계정 삭제를 **같은 연결·트랜잭션**에서 처리한다.

| 먼저 회원 잠금을 얻은 요청 | 뒤에 처리되는 요청 |
| --- | --- |
| 선물 주문 | 주문 커밋 후 선물을 확인하고 탈퇴를 409 `ACCOUNT_HAS_UNUSED_GIFTS`로 거절 |
| 계정 탈퇴 | 탈퇴 커밋 후 수신자가 없음을 확인하고 주문을 404 `RECEIVER_NOT_FOUND`로 거절 |

## 구현 범위

- `controllers/usersController.js`: 기존 회원 잠금을 유지하고, 잠금 이후 미사용 선물을 확인한다. 대기 중 다른 탈퇴가 완료됐다면 401 `UNAUTHORIZED`를 반환한다.
- `db/models/giftModel.js`: `hasUnusedGiftsForUpdate(receiverId, connection)`으로 결제 완료·미사용 선물 존재 여부만 조회한다. 전달된 연결에서 `FOR UPDATE`로 최신 상태를 읽으며 상품·리뷰 목록 조인은 하지 않는다.
- 단건 주문, 장바구니 주문 그룹, 즉시 구매 주문 그룹은 이미 `cartTransaction.lockUsers`로 발신자·수신자를 ID 순서대로 잠근다. 해당 주문 코드는 변경하지 않는다.
- 본인 구매도 미사용 선물에 포함한다. 사용 완료 선물만 있으면 탈퇴할 수 있으며, 활성 정지 차단과 탈퇴 후 세션·쿠키 정리는 유지한다.
- API 주소·요청 형식·기존 오류 코드·ERD 변경 없음. **마이그레이션과 FE 수정은 필요 없다.** 주문 취소 기능은 별도 작업이다.

## 검증 방법

환경 준비는 [테스트 가이드](TESTING.md)를 따른다. 운영 DB나 운영 DB 터널에서는 실행하지 않는다.

```bash
npm test -- --runInBand
npm run test:withdrawal:db -- .env.test.local
```

DB 테스트는 임의 이름의 `withdrawal_test_*` DB를 생성하고 완료 시 삭제한다. 기존 `DB_NAME`은 사용하지 않는다.
인증은 테스트 세션을 주입하되 라우터·인증 DB 조회·컨트롤러·모델·SQL은 실제 코드로 실행한다.
Redis는 테스트 안에서 격리하며 공유 캐시에 접근하지 않는다.

- 첫 요청을 COMMIT 직전에 잠시 대기시키고 두 번째 요청을 실행한다.
- `performance_schema`로 두 번째 요청이 첫 요청의 **users 행 잠금**을 기다리는지 확인한다. 단순히 시간을 지연한 결과만으로 동시성을 판단하지 않는다.
- 첫 요청을 커밋한 후 두 번째 응답과 DB 결과를 확인한다.
- `REPEATABLE READ`와 `READ COMMITTED` 각각에서 단건·즉시 구매·장바구니 주문을 검증한다.
- 주문 선행/탈퇴 선행 총 12개 경합 시나리오에서 응답 코드, 수신자 보존, 주문·선물·그룹 수, 장바구니 보존/삭제, 수신자 없는 주문 발생 여부를 확인한다.
- 본인 구매, 사용 완료 후 탈퇴, 활성 정지/해제 후 탈퇴도 확인한다.

## 로컬 검증 결과 — 2026-10-30

- 기준: `develop`의 `1ee484e`에 이번 변경 적용. Node.js 24.11.1, 별도 로컬 MySQL 8.0.46.
- Jest: 53개 suite / 866개 test 통과.
- 실제 MySQL: 경합 시나리오 12개를 포함해 총 71개 assertion 통과. 임시 DB 삭제 확인.
- 기존 즉시 구매 DB 회귀 테스트(`test:direct-orders:db`): 55개 assertion 통과. 장바구니·기존 단건 주문 호환 검증도 포함한다.
- 같은 DB 테스트에서 탈퇴 컨트롤러만 변경 전 코드로 메모리상 교체하면 첫 시나리오가 실패했다. 기대값은 `ACCOUNT_HAS_UNUSED_GIFTS`지만 실제로는 `ACCOUNT_DELETE_SUCCESS`가 반환돼 기존 레이스를 재현했다. 작업 파일은 변경하지 않았다.
- 브라우저·실제 세션 쿠키·운영 배포 검증 결과는 아니다. 운영 DB와 운영 서버는 변경하지 않았다.
